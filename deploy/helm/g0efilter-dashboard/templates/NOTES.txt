{{ if not (or .Values.secrets.apiKey (and .Values.secrets.existingSecret .Values.secrets.existingSecretKeys.apiKey)) -}}
Sidecars need a machine API key to ship logs. One was generated and printed at
startup when the key store was empty:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "g0efilter-dashboard.fullname" . }} | grep -i 'api key'
{{- end }}

Point a sidecar at it. Both the host and the API key belong in the EgressPolicy, and
the policy has to allow the dashboard itself - a sidecar filters its own egress:

  apiVersion: g0efilter.io/v1alpha1
  kind: EgressPolicy
  metadata:
    name: web
  spec:
    podSelector:
      matchLabels:
        app: web
    sidecar:
      dashboard:
        host: http://{{ include "g0efilter-dashboard.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}
        apiKeySecretRef:
          name: g0efilter-dashboard-key
          key: api-key
    egress:
      - name: dashboard
        to:
          - domainNames: ['{{ include "g0efilter-dashboard.fullname" . }}.{{ .Release.Namespace }}.svc']

The Secret named there is read by kubelet in the workload's own namespace, so copy
the key into each namespace that ships logs.
